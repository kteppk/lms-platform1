# 0.8.0 — люди, профили и справочник

В каждом кабинете появились разделы «Люди» и «Справочник». Поиск людей выполняется на сервере по словам ФИО и текущей роли, с учётом регистра и е/ё. Порядок стабилен по имени и ID; страница содержит до 30 записей. Пользователям доступны имя, роль, фотография и ссылка на профессиональный профиль преподавателя. Email, результаты, документы студентов и служебные данные в поиск не включаются.

В «Мой профиль» все три роли могут выбрать фото из файла/галереи, вставить изображение из буфера, увидеть предпросмотр, сохранить и удалить снимок. Поддерживаются JPG, PNG, WebP до 5 МБ. Клиент уменьшает изображение до 512 пикселей по длинной стороне и перекодирует его, убирая исходные метаданные и уменьшая трафик. Сервер проверяет владельца пути, реальный размер и MIME загруженного объекта. Подписанные ссылки живут час; хранилище остаётся закрытым. Фото и данные каталога людей не сохраняются в офлайн-кэше приложения.

Новая таблица account_avatars хранит одну фотографию аккаунта с ревизией. Миграция переносит существующие ссылки преподавателей, не копируя файлы и не меняя роли. Старый API профессионального профиля продолжает работать: изменения фото синхронизируются с общим профилем. Конфликт из другой вкладки не перезаписывает актуальное фото. Неиспользуемые заменённые изображения удаляются, используемые в документах сохраняются.

В профиле есть сворачиваемая форма смены пароля: старый пароль, новый и повтор нового. Перед изменением Firebase Auth выполняет reauthenticateWithCredential, затем updatePassword. Новые пароли принимаются длиной 8–128 символов. Пароли не отправляются в Supabase и не записываются в хранилище приложения. Поля очищаются после успеха; неверный старый пароль не меняет пароль аккаунта. Использована официальная документация: https://firebase.google.com/docs/auth/web/manage-users#re-authenticate_a_user.

Новости, карточки центра уведомлений и тосты получили тёмную заливку, светлый текст, видимые рамки и отступы. Теги новостей и цветные признаки непрочитанного/важного события сохранены. Меню «⋯» остаются светлыми и читаемыми; красный крестик на тёмном фоне имеет светлый красный оттенок.

Справочник содержит поиск и ответы про вход/ФИО, предметы, материалы, расписание, подписки, слабый интернет, тесты, проверку работ, результаты и работу администратора. В нём находится кнопка «Идеи, улучшения и ошибки». Поскольку Google Форма ещё не создана, кнопка недоступна и подписана «Форма скоро появится». Администратор может открыть «Подключить Google Форму» и сохранить ссылку forms.gle или docs.google.com/forms; после этого кнопка открывает форму в новой вкладке. Настройки изменяются с проверкой роли и ревизии. Сохранение ссылки не рассылает общих уведомлений.

API: searchPeople, getPerson, createAvatarUpload, saveMyAvatar, removeAvatarUpload, getPortalSettings, savePortalSettings. Доступ только после проверки Firebase ID token; все новые таблицы и RPC закрыты для прямого доступа anon/authenticated. Фото меняется только для UID проверенного пользователя; ссылку формы настраивает только администратор.

Миграция: 20261115000100_people_avatars_settings.sql. Порядок публикации: миграция, функция lms, GitHub Pages. Новая версия статического кэша — 0.8.0. Открытая попытка теста не перезагружается принудительно.

Проверки: 45 тестов бизнес-логики, Deno check, локальные сценарии с настоящим Firebase Auth Emulator и PostgreSQL/PGlite, включая вход старым/новым паролем после смены, загрузку/удаление фото для каждой роли, сохранение после перезагрузки, изоляцию чужих файлов, поиск/приватность, справочник и настройки формы. Проверки архива, ручных ответов, истории, Excel, печати и офлайн-черновиков сохранены. Мобильная проверка охватывает три роли и восемь размеров экрана. Проверки публикации используют только отдельные временные аккаунты, без общей рассылки и без подключения фиктивной Google Формы.
