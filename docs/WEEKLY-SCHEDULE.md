Недельное расписание

Расписание повторяется каждую неделю, как на бумажном образце. Студент и преподаватель выбирают группу; выбор сохраняется в браузере отдельно для каждого аккаунта. Сервер возвращает занятия только выбранной группы. На телефоне дни расположены последовательно, на большом экране — в несколько колонок. Внутри дня: номер пары, предмет, преподаватель, аудитория. Время не выдумывается: его можно указать в редакторе, если известны звонки.

Администратор открывает «Расписание», выбирает или добавляет группу и нажимает на ячейку. В редакторе доступны «Занятие» и «Нет пары». Предмет и ФИО можно выбрать из подсказок или вписать вручную, в том числе для ещё не зарегистрированного преподавателя. «Нет пары» очищает данные занятия, сохраняя явное состояние ячейки. Отсутствующая запись означает «Не заполнено». Изменение действует каждую неделю. Для воскресенья есть отдельный раскрывающийся блок.

`study_groups` содержит название, курс, специальность и число пар в день (1–12). `weekly_schedule_cells` принадлежит группе и имеет уникальную позицию `(group_id, weekday, lesson_number)`. Связи с предметом и аккаунтом преподавателя необязательны; текстовые подписи позволяют перенести бумажное расписание. `revision` и ожидаемый ID предотвращают потерю одновременных правок. Проверка роли администратора есть и в Edge API, и внутри SQL-транзакции. Прямой доступ anon/authenticated закрыт RLS и привилегиями. Изменения автоматически создают уведомления; повторное сохранение тех же данных не создаёт лишних событий.

API функции `lms`: `listScheduleGroups`, `getWeeklySchedule({groupId})`, `createScheduleGroup({name,course,program,lessonsPerDay})`, `saveScheduleCell({groupId,weekday,lessonNumber,id,revision,status,title,subjectId,teacherId,teacherLabel,room,note,startsAt,endsAt})`. Чтение требует входа, запись — администратора. `status` — `lesson` или `free`. При создании ожидается `id:null`, при редактировании — ID и версия из последнего чтения. Устаревшая версия возвращает 409; введённые значения остаются в редакторе до обновления.

Миграция `20261112000100_weekly_schedule.sql` сохраняет прежние `schedule_entries`. Группы из них добавляются в каталог, прежние занятия с датой показываются отдельным блоком для выбранной группы на текущей неделе. Старый API `listSchedule` фильтрует по точному названию; без группы обычным пользователям записи не возвращаются. Учебные материалы, тесты, результаты и роли миграция не изменяет.

`supabase/seed-weekly-schedule.json` — перенос двух полностью видимых колонок фотографии (9241 и 9251), понедельник–пятница. Обрезанная суббота и группа 9261 не восстановлены. У неуверенно читаемых подписей преподавателя оставлено примечание. Импорт выполняется `scripts/import-weekly-schedule.cjs` через доверенный Supabase CLI с UID существующего администратора; он не назначает роли и не перезаписывает существующие ячейки.

Проверки: `npm test` проверяет миграцию, права, версии, одновременное создание, явное отсутствие пары и прежние попытки/оценки. `tests/schedule-browser.cjs` проверяет настоящий API и оба кабинета с изолированными аккаунтами; вызывающий скрипт отвечает за очистку. `npm run test:mobile` проверяет восемь размеров экрана, все разделы и восстановление тестовой попытки с изолированными API-ответами.
