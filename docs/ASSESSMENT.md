**Попытки, журнал и ручная проверка**

Миграция: `supabase/migrations/20261111000100_assessment.sql`.

Каждая попытка хранит снимок вопросов с ключами, заголовком, автором и предметом. Эти данные доступны только серверу; студент получает вопросы без ключей. Архивирование теста скрывает новые старты, но сохраняет возможность продолжить ранее начатую работу. Старые материалы и предметы сохраняют прежний формат.

На студента и тест допускается одна активная попытка. Повторное открытие возвращает её ID и прежний срок окончания. Запись черновика и отправка используют номер версии: запрос из устаревшего окна отклоняется, а не перезаписывает новые ответы. Завершение идемпотентно. При позднем обращении сервер завершает работу по последнему сохранённому черновику; в пределах прежнего допуска 15 секунд принимает окончательную отправку. Просроченные работы завершаются также при следующем чтении попытки или списка активных работ. Отдельный фоновый планировщик не установлен.

В браузере сохраняется локальная копия несохранённых ответов, отдельно для каждого пользователя и попытки. Она помогает после перезагрузки и сбоя сети. Серверная версия остаётся основной. При конфликте локальная копия не накладывается на новую серверную версию автоматически; её можно скачать для сверки. Выход из формы сохраняет черновик и оставляет работу в блоке «Незавершённые работы».

Каждый вопрос даёт максимум 1 балл. Выбор ответа оценивается автоматически; наличие текстовых или фотоответов переводит работу в `pending_review`, без итогового процента и сообщения о зачёте. Преподаватель выставляет 0 или 1 за каждый ручной вопрос и общий комментарий. После проверки статус становится `graded`, процент рассчитывается сервером. Изменение проверки требует актуального номера версии и оставляет запись в `test_result_reviews`.

Преподаватель видит и проверяет только работы собственных тестов. Студент видит только собственную историю, комментарии и фотографии. Право проверять работы не выдаётся другому преподавателю через присоединение к тому же предмету. Фотографии выдаются по временным ссылкам из закрытого бакета. Изменение роли применяется сервером на каждом обращении.

**Действия API**

Все запросы: `POST /functions/v1/lms`, Firebase Bearer token, `{ action, data }`.

| Действие | Данные |
| --- | --- |
| `startStudentTest` | `testId`: создать либо возобновить попытку |
| `getStudentAttempt` | `attemptId`: восстановить ответы, срок и результат |
| `listActiveAttempts` | активные попытки текущего студента; просроченные завершаются |
| `saveStudentDraft` | `attemptId`, `revision`, полный объект `answers` |
| `submitStudentTest` | `attemptId`, `revision`, полный объект `answers` |
| `deleteItem` с `kind: "tests"` | `id`: архивировать собственный тест |
| `listResults` | необязательные `status`, `testId`, `studentName` (для преподавателя), `fromDate`, `toDate`, `offset` |
| `getResult` | `resultId`: вопросы, ответы, баллы, комментарий; ключи вариантов и история проверок доступны только автору-преподавателю |
| `reviewResult` | `resultId`, `revision`, объект `grades` по индексам всех ручных вопросов, `feedback` |

Список результатов возвращается страницами по 50 записей. Даты фильтра применяются по UTC и обозначены в интерфейсе. CSV использует текущие фильтры, включает до 5000 работ и защищает текстовые ячейки от формул. Привязки к учебным группам в этом выпуске не вводились.

Миграция заполняет снимки имеющихся попыток по сохранённым тестам. Если исходный тест уже удалён, его вопросы восстановить невозможно; старый итог остаётся в истории. Из нескольких прежних активных попыток одного теста сохраняется последняя; остальные получают `superseded`. Старые результаты со снимком и ручными вопросами переводятся в ожидание проверки. Имеющийся результат без доступной версии вопросов не выдаётся за заново проверенную работу.

**Проверка и выпуск**

`npm ci` и `npm test` запускают проверки настоящих SQL-функций в PGlite: миграция над существующими записями, возобновление, версии черновика, архивирование, истечение срока, ручная проверка и запрет чужих фото. `tests/assessment-browser.cjs` содержит общий браузерный сценарий для подготовленных локальных либо временных рабочих аккаунтов, включая сбой сохранения, восстановление, PDF/фото и журнал. Создание и удаление аккаунтов выполняет внешний проверочный стенд; сам модуль не подключается к рабочей базе автоматически.

Порядок выпуска: применить миграцию в выбранном Supabase-проекте, развернуть `lms`, опубликовать HTML/JS/CSS на GitHub Pages. Сохранён совместимый SQL-вход `submit_test_attempt` на время обновления функции. После выпуска проверить вход в оба кабинета, восстановление попытки, завершение архивного теста, ручную оценку, студенческую историю, ограничения чужого доступа и сохранность прежних материалов. Проверочные файлы и аккаунты удаляются отдельно от пользовательских данных.
