# VPS Masterhost

Основной адрес: https://kteppk.ru/

Домен и `www` направлены A-записями на VPS `90.156.141.103`. Nginx обслуживает платформу на основном домене, а HTTP, `www` и прежний адрес `vm756327.vps.masterhost.tech` перенаправляет на HTTPS основного домена, сохраняя путь и параметры. Старые service worker выдаются без перенаправления, очищают прежний офлайн-кэш и переводят открытые вкладки на новый домен. Сертификаты обоих адресов автоматически продлеваются через certbot; HTTP-путь ACME остаётся доступным на каждом домене.

`PUBLIC_URL` в закрытом `/etc/lms/runtime.env` должен быть `https://kteppk.ru` без завершающего слеша: он используется для проверки Origin, выдачи JWT, ссылок восстановления и подписанных ссылок на файлы. Секреты, аккаунты и база при смене адреса сохраняются. Сеансы и разрешения браузера привязаны к домену: на новом адресе нужно войти и включить системные уведомления заново; подписки на группы остаются в базе.

На VPS работают Nginx, Node.js и PostgreSQL. Аккаунты находятся в закрытой схеме `app_auth`, учебные данные — в `public`, загруженные файлы — в `/var/lib/lms/storage`. Firebase и Supabase не нужны для работы перенесённой платформы. ID аккаунтов и прежние пароли сохраняются; при первом успешном входе старый хэш пароля заменяется локальным scrypt.

## Проверка и обновление

`systemctl status lms nginx postgresql` показывает состояние служб. `curl http://127.0.0.1:8080/healthz` проверяет приложение и подключение к базе. Журнал приложения: `journalctl -u lms`. Порт приложения доступен только локально; снаружи открыты HTTPS, HTTP для перенаправления/сертификата и SSH.

Перед загрузкой серверного кода выполните `node scripts/build-vps.cjs` на компьютере разработчика. Он собирает JavaScript в `server/runtime`; это необходимо и для сборок Node.js без поддержки TypeScript. Загрузите сервер, runtime, package-lock, миграции и публичные файлы. В `/var/www/lms` должны находиться только публичные файлы, без `server`, `.git`, резервных копий или конфигурации с секретами. После обновления: `systemctl restart lms`. Не запускайте первоначальный импорт данных поверх работающей платформы: он заменяет таблицы и аккаунты.

Секреты хранятся в `/etc/lms/runtime.env`, параметры старых хэшей — в `/etc/lms/firebase-hash-config.json`. Эти файлы нельзя добавлять в Git, публиковать или пересылать в сообщениях. Служба `lms` работает отдельным системным пользователем. Сертификат Let's Encrypt продлевает certbot.

## Резервные копии

`lms-backup.timer` ежедневно запускает `/opt/lms/server/deploy/backup.sh`. В `/var/backups/lms/<UTC-дата>` сохраняются дамп PostgreSQL, закрытая конфигурация и снимок файлов. Снимки файлов используют жёсткие ссылки: неизменённые файлы не занимают место повторно. Хранятся семь дней. `systemctl start lms-backup.service` создаёт копию вручную. Проверяйте свободное место и состояние таймера. Локальная исходная копия миграции хранится отдельно, вне Git.

Для восстановления остановите приложение; восстановите дамп в отдельную проверочную базу и проверьте его до замены рабочей базы. Затем восстановите файлы и конфигурацию из той же копии, владельца `lms:lms` у рабочего хранилища и запустите приложение. Не удаляйте рабочую базу без отдельной резервной копии.

## Восстановление доступа и уведомления

SMTP не настроен по решению владельца. Пользователь оставляет запрос на странице входа. Администратор в списке аккаунтов видит запросы и создаёт одноразовую ссылку, действующую 30 минут. Ссылку передают пользователю лично. После смены пароля прежние сеансы отзываются.

Разрешения браузера привязаны к адресу сайта. После переезда пользователь должен снова включить системные уведомления на новом адресе. Подписки на группы сохраняются. Напоминания за пять минут остаются отдельной экспериментальной функцией с явным согласием пользователя. Планировщик запускается внутри службы `lms`; старый планировщик Supabase должен быть остановлен.

Исходные облачные данные сохранены как резерв на время проверки переезда. Старый LMS API закрыт для изменений, чтобы данные не расходились между двумя системами. GitHub Pages служит перенаправлением, исходный код платформы хранится в ветке `main`.

## Обновления в реальном времени (0.10.1)

Одно SSE-соединение `/events` передаёт короткие сигналы об изменениях. PostgreSQL отправляет их после фиксации транзакции через `LISTEN/NOTIFY`. Сами сообщения, результаты, профили и материалы браузер получает через прежний API с проверкой доступа. Тексты переписки, персональные поля и токены в поток не помещаются.

Закрытый поток использует существующий HttpOnly-cookie сеанса. Роль и действительность сеанса проверяются перед рассылкой и каждые 15 секунд. Отзыв роли закрывает прежний поток и очищает интерфейс чата. Гость подключается с `public=1` и получает только сигналы новостей, списка групп и выбранного расписания. Изменения других групп не отправляются в этот поток. Подписки на оповещения остаются отдельными от просмотра расписания.

При обрыве связи браузер переподключается с увеличением интервала ожидания. После подключения заново читает актуальные данные; чат догружает пропущенные сообщения по курсору. Для скрытой вкладки поток приостанавливается. Если поток недоступен, остаётся периодическая проверка. Редактируемые формы и активные тесты не перерисовываются. Новости сохраняют фильтры и открытые тексты; новые оценки обновляют результаты без перезагрузки.

Для существующей базы применяйте **только** `server/realtime-schema.sql` через PostgreSQL с `ON_ERROR_STOP=1` и одной транзакцией. Этот скрипт добавляет функции и триггеры, сохраняя все строки. Первоначальный `server/migrate.mjs` для обновления рабочей базы запускать нельзя. Соберите runtime и архив командами `node scripts/build-vps.cjs` и `node scripts/package-vps.cjs <каталог>`. Настройки Nginx из `server/deploy/nginx.conf` отключают буферизацию для `/events` и включают HTTP/2. После установки перезапустите `lms` и проверьте `/healthz`, гостевой поток и поток авторизованного пользователя. Дополнительных библиотек и платных сервисов не требуется.

## Непрочитанные сообщения (0.10.2)

Перед обновлённым `server/realtime-schema.sql` примените миграцию `supabase/migrations/20261119000100_curator_chat_unread.sql`. Она хранит монотонный указатель прочтения в `curator_chat_reads` для каждого аккаунта. Собственные сообщения в счётчик не входят. При первом применении существующая история считается прочитанной для действующих кураторов и администраторов; повторное применение не сбрасывает новые непрочитанные сообщения. Новые сообщения вставляются последовательно, чтобы указатель не пропускал сообщения параллельных отправителей.

API `getCuratorChatSummary` и `markCuratorChatRead` доступны только текущим кураторам и администраторам и используют ID проверенного аккаунта. Чат отмечает прочитанными только уже загруженные сообщения при видимом открытом разделе. Событие `chat-unread` уходит только этому аккаунту, синхронизируя его вкладки. В других разделах появляются всплывающие уведомления с переходом в чат. На телефоне счётчик также виден на кнопке «Ещё». Приватные тексты не сохраняются в браузерном кэше и не передаются в SSE.

## Версия 1.0.0

Перед новым `server/realtime-schema.sql` примените только миграцию `20261119000200_subject_join_requests.sql`. Она добавляет заявки преподавателей и сохраняет все существующие назначения. Старый API `joinSubject` отклоняет прямое присоединение. `requestSubjectJoin` создаёт одну ожидающую заявку, `reviewSubjectJoinRequest` доступен только администрации, включая проверку роли внутри SQL. Повторное одинаковое решение идемпотентно; противоположное требует обновить список. Уведомления о заявках получают администраторы, о решении — заявитель. Исходный импорт данных при обновлении не запускается.

Администрация видит «Онлайн сейчас» в разделе «Аккаунты и роли». Нативный API `getOnlineStats` повторно проверяет действующую роль администратора и возвращает агрегаты активных SSE-подключений: уникальные ID аккаунтов, разбивку по ролям и количество гостевых соединений. Имена, IP и идентификаторы сеансов не возвращаются. Сигналы `presence` отправляются только администрации. Скрытая вкладка закрывает соединение; при потере сети возможна задержка до обнаружения разрыва. Показатель означает открытый видимый сайт, а не активность клавиатуры. Счётчик предназначен для одного экземпляра приложения на текущем VPS.

Чат занимает отдельный экран телефона с закреплённой строкой ввода. История загружается порциями с сохранением позиции, новые сообщения не сбрасывают чтение старой переписки. Черновик хранится только в памяти текущей страницы на аккаунт и удаляется при уходе со страницы. На ПК Enter отправляет, Shift+Enter переносит строку; на телефоне Enter переносит строку, отправка — отдельной кнопкой. После изменений собирайте runtime и архив обычными скриптами. Профиль преподавателя сохраняет опубликованный ранее текст `bio`, но новое поле «О себе» больше не выводится и не изменяется.
