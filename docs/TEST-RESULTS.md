Результаты выбранного теста

Раздел преподавателя «Результаты тестов» заменяет прежний список «Журнал оценок». Внутренний ключ `journal` сохранён для старых ссылок из уведомлений. Отдельного журнала с посещаемостью, весами работ и периодами нет. Существующие попытки, ответы, баллы и история ручных проверок не изменяются миграцией.

Преподаватель выбирает тест или нажимает «Результаты» в карточке своего теста. По умолчанию показана последняя сданная попытка каждого студента, включая ожидающую ручной проверки. Фильтр статуса применяется после выбора последних попыток. «Все попытки» показывает полную историю; кнопка «История» ограничивает список одним студентом. Номер попытки определяется по всей истории теста до фильтрации. Доступны поиск по сохранённому ФИО, сортировка по ФИО, дате и результату, страницы по 50 записей.

Студент выбирает тест в «Мои результаты» и видит только собственные попытки. Оба списка включают архивные тесты и сохранённые результаты ранее удалённых тестов. Удалённому тесту нельзя настроить новую шкалу, но его результаты остаются доступны.

Баллы и процент проверенной работы показаны отдельно от отметки 2–5. У непроверенных ответов итоговые поля пусты. Шкалы по умолчанию нет: преподаватель задаёт три целых возрастающих порога процентов для 3, 4 и 5. Ниже первого порога — 2. При сравнении используются исходные баллы без округления процента: 2/3 ниже 67%, хотя старое целочисленное поле процента равно 67. Изменение шкалы пересчитывает отметки попыток, сохраняя исходные баллы и проверки. Сохранение требует актуальной версии шкалы.

Выгрузка «Скачать Excel (.xlsx)» и «Печать» включают весь отфильтрованный список с той же сортировкой, а не только открытую страницу. До 5000 попыток за запрос; больший список требует уточнения фильтра. Сервер возвращает строки, шкалу и число результатов одним SQL-запросом, поэтому выгрузка не смешивает страницы разных состояний базы. В заголовке указаны тест, фильтры, шкала и момент формирования. Время отображается по Asia/Krasnoyarsk (Кызыл, UTC+7).

`results-export.js` формирует один лист XLSX в формате OOXML. Баллы, проценты, отметки и даты — числовые ячейки; даты представлены местным временем Кызыла. Текстовые поля используют `inlineStr`, поэтому пользовательская строка, начинающаяся с `=`, не выполняется как формула. Файл не содержит макросов и внешних ссылок. Заголовок закреплён, включён фильтр. Для печати используется отдельный iframe с экранированным содержимым, повторяемой шапкой и альбомной страницей A4. Меню кабинета и посторонние данные в печать не попадают.

Новые действия `POST /functions/v1/lms`:

| action | data |
| --- | --- |
| `listResultTests` | каталог доступных тестов, включая архивные и сохранённые результаты |
| `getTestResults` | `testId`, `mode: latest/all`, `status`, `studentName`, `studentId`, `sort: name/date/score`, `offset` |
| `exportTestResults` | те же фильтры; доступно только преподавателю; все строки одним снимком |
| `saveTestGradingScale` | `testId`, `revision` (-1 для ещё не заданной шкалы), `minThree`, `minFour`, `minFive` |

`getResult` и `reviewResult` сохраняют прежние правила доступа и формат ручной проверки. `listResults` остаётся совместимым со старым клиентом. Каталог, таблица и шкалы проверяют текущую роль; преподаватель читает только собственные тесты и работы, студент — только свои результаты. Присоединение к предмету не открывает чужие ответы. RLS и SQL-привилегии закрывают прямое обращение анонимных клиентов.

Миграция: `20261113000100_test_results_table.sql`. Добавляется только таблица шкал и функции чтения/сохранения; тесты и результаты не переписываются. Порядок выпуска: миграция, функция `lms`, статические файлы GitHub Pages.

Проверки: `npm test` — миграция, история/нумерация попыток, фильтры, шкалы, конфликты, экспорт больше страницы и ограничения доступа. `tests/assessment-browser.cjs` — восстановление, архив, текст/фото, ручная проверка и выгрузка XLSX. `tests/results-browser.cjs` — две реальные попытки, таблица/история/шкала, права, скачивание и печать, защита от устаревшего ответа. `npm run test:mobile` — три кабинета, восемь размеров экрана, сохранность незавершённой попытки. Сквозные стенды создают изолированные аккаунты; вызывающий стенд обязан удалить их и принадлежащие им строки/файлы.
