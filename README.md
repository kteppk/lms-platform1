# LMS Platform

GitHub Pages публикует HTML и JavaScript. Firebase Authentication отвечает за вход, Cloud Firestore хранит учебные данные, Cloud Storage хранит вложения. Cloud Functions создают тесты, выдают студентам вопросы и сохраняют рассчитанные на сервере результаты.

## Развёртывание

1. В Firebase-проекте `students-70392` проверьте, что включён вход Email/Password, создана база Cloud Firestore по умолчанию и настроен бакет из `firebase-config.js`. Для Cloud Functions и Cloud Storage необходим тариф Blaze.
2. Войдите в Firebase CLI под учётной записью с правами развёртывания. Сверьте существующие настройки Firestore, Storage и список подтверждённых преподавателей перед применением правил.
3. Установите зависимости и разверните серверную часть. Дождитесь готовности составных индексов Firestore.

```powershell
npm --prefix functions ci
firebase login
firebase deploy --project students-70392 --only functions,firestore,storage
```

4. При первом развёртывании правил Storage подтвердите запрос Firebase CLI на подключение правил Storage к Firestore. Storage проверяет подтверждение преподавателя через документ Firestore.
5. В GitHub откройте **Settings → Pages** и проверьте, что источником публикации выбраны **Deploy from a branch**, **main**, **/(root)**. После развёртывания Firebase отправьте обновление в `main`. Проверьте статус развёртывания во вкладке **Actions** и откройте [сайт](https://kteppk.github.io/lms-platform1/).

## Роли и существующие данные

- Каждый новый аккаунт начинает со студенческого кабинета. Чтобы выдать преподавателю доступ, администратор находит его UID в Firebase Authentication и создаёт документ `teachers/{UID}` в Firestore, например с полем `approved: true`. Доступ определяется наличием документа. Новый вход или перезагрузка кабинета применяет роль. Для отзыва доступа администратор удаляет этот документ.
- Существующие профили, материалы и тесты читаются из прежних коллекций. Для прежних преподавателей требуется подтверждение по UID. Поле `users.role` используется для списка студентов и синхронизируется при входе. Если у старого аккаунта отсутствует профиль, приложение восстанавливает его при входе.
- Студент получает тест через Cloud Functions без правильных ответов. Баллы сохраняет только сервер, а повторная отправка той же попытки возвращает сохранённый результат. Как и прежде, автоматически засчитываются только правильные ответы на вопросы с выбором, а в знаменателе учитываются все вопросы. Ранее записанные результаты остаются в базе с исходными баллами.
- Ссылки на вложения лекций и книг действуют у любого, кто получил ссылку. Фотоответы новых попыток сохраняются как пути в Storage, без ссылки на скачивание в результате.

## Локальная проверка

Требуются Node.js 22, Firebase CLI и Java для эмулятора Firestore. Сайт на `localhost` или `127.0.0.1` подключается к демонстрационному проекту.

```powershell
npm --prefix functions ci
firebase emulators:start --project demo-lms-platform --only auth,firestore,functions,storage
```

Раздайте корень репозитория локальным HTTP-сервером, например `python -m http.server 8000 --bind 127.0.0.1`. Откройте [сайт](http://127.0.0.1:8000/) и [Emulator Suite](http://127.0.0.1:4000/).

Зарегистрируйте два тестовых аккаунта и подтвердите один как преподавателя через Firestore в Emulator Suite. Из кабинета преподавателя опубликуйте лекцию и тест. Убедитесь, что студент видит материалы, получает балл после отправки теста и попадает в свой кабинет при открытии `teacher.html`. В Firestore проверьте наличие профилей и записи в `test_results`.
