# LMS Platform

GitHub Pages публикует HTML и JavaScript. Вход и регистрация используют Firebase Authentication проекта `students-70392`. Supabase хранит профили, материалы, тесты и вложения. Edge Function `lms` проверяет токен Firebase и выдаёт данные в соответствии с ролью. PostgreSQL сохраняет результат теста одной транзакцией.

## Публикация

1. Создайте проект Supabase на тарифе **Free**. Войдите в Supabase CLI и узнайте идентификатор проекта.

```powershell
supabase login
supabase projects list
supabase link --project-ref PROJECT_REF
supabase db push --remote --yes
supabase functions deploy lms --remote=PROJECT_REF --use-api --yes
```

2. В `firebase-config.js` укажите публичный URL проекта `https://PROJECT_REF.supabase.co` в `supabaseProjectUrl`. Секретные ключи предоставляет среда Edge Function.
3. В репозитории GitHub проверьте **Settings → Pages → Deploy from a branch → main → /(root)**. Отправьте изменения в `main` и дождитесь развёртывания. [LMS на GitHub Pages](https://kteppk.github.io/lms-platform1/)

## Роли и файлы

При первом входе создаётся профиль студента. Чтобы назначить преподавателя, откройте таблицу `profiles` в Supabase, найдите ID его профиля и добавьте этот ID в `teachers.user_id`. Новый вход или перезагрузка страницы применит роль. Чтобы отозвать доступ, удалите запись из `teachers`.

Лекции и книги доступны вошедшим пользователям. Вложения хранятся в закрытых бакетах и скачиваются по ссылкам с ограниченным сроком действия. Один учебный файл может занимать до 50 МБ, фотоответ — до 10 МБ. На одну лекцию можно прикрепить до 20 файлов.

Студенты получают вопросы без ключей ответов. При повторной отправке той же попытки сервер возвращает уже сохранённый результат. Автоматически засчитываются ответы с выбором варианта, а в знаменателе учитываются все вопросы.

## Предметы

- **Student** — запись в `profiles` без соответствующей записи в `teachers`. Попытки и результаты связываются со студентом через `student_id`.
- **Teacher** — запись в `teachers`, связанная с `profiles` через `user_id`. Таблица `subject_teachers` связывает преподавателей и предметы «многие ко многим».
- **Subject** — запись в `subjects`. Создатель автоматически становится одним из преподавателей предмета и может изменить название, описание или убрать предмет из каталога. Другие преподаватели могут самостоятельно присоединиться и выйти. Удаление из каталога архивирует предмет. Опубликованные записи и результаты сохраняются.
- **Material** — лекция или книга в `materials`. Запись хранит автора, файлы и необязательный `subject_id`. В `tests` действует такая же привязка по паре `subject_id` и `teacher_id`. Старые записи получают пустой `subject_id` и доступны в обычных вкладках. После выхода преподавателя из предмета его материалы скрываются в этом предмете до повторного присоединения.

Все операции идут через `POST /functions/v1/lms` с токеном Firebase и телом `{ "action": "...", "data": { ... } }`. Функция проверяет роль, а PostgreSQL при записи проверяет, что преподаватель ведёт активный предмет.

| Действие API | Вход и результат |
| --- | --- |
| `listSubjects` | Активные предметы и число преподавателей. Преподаватель также получает свои признаки участия и права редактирования. |
| `saveSubject` | `title`, `description`, необязательный `subjectId`. Создание предмета и привязка автора выполняются одной транзакцией. |
| `joinSubject`, `leaveSubject`, `deleteSubject` | `subjectId`. Присоединение или выход текущего преподавателя, либо архивирование создателем. |
| `createUpload` | `kind`, `mime`, `size`, необязательный `subjectId`. Возвращает путь и временную ссылку для загрузки в закрытый бакет. |
| `createMaterial`, `createTest` | Данные лекции, книги или теста и необязательный `subjectId`. Для файла также сохраняются имя и тип из хранилища. |
| `listSubjectTeachers` | `subjectId`. Возвращает список преподавателей с именами. |
| `getSubjectContent` | `subjectId` и `teacherId`. Студент получает лекции, книги, временные ссылки на файлы и список тестов только для этой пары. |

В кабинете преподавателя вкладка **Предметы** содержит форму и два списка — свои предметы и другие предметы, к которым можно присоединиться. В форме лекции, книги или теста преподаватель выбирает предмет из тех, которые ведёт.

В кабинете студента путь выглядит так:

```text
Предметы → Карточка предмета
             ├─ Один преподаватель → Материалы преподавателя
             └─ Несколько → Карточки с именами и инициалами → Выбор

Материалы преподавателя → Видео с плеером
                        → PDF и книги с просмотром и скачиванием
                        → Лекции с текстом и вложениями, включая PPT и PPTX
                        → Тесты с привычной формой прохождения и результатом
```

Для выпуска обновления сначала примените миграцию `20261110000200_subjects.sql` через `supabase db push --remote --yes`, затем разверните Edge Function `lms` и опубликуйте фронтенд. Уже сохранённые попытки и результаты тестов сохраняют прежний формат.

## Локальный запуск

Запустите Supabase CLI с Docker и примените миграцию к локальной базе.

```powershell
supabase start
supabase db reset
supabase functions serve lms
```

Раздайте корень репозитория по HTTP, например `python -m http.server 8000 --bind 127.0.0.1`. При открытии [локального сайта](http://127.0.0.1:8000/) данные и файлы идут в локальный Supabase, а вход использует Firebase Auth проекта `students-70392`.
